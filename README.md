# White House — Каспийск

Каталог женской одежды White House, ул. Ленина, 39А. Структура витрины вдохновлена Visage Hall; исходные фотографии, модели и цены взяты из предоставленного владельцем примера магазина.

[Открыть сайт](https://podlivochka.github.io/white-house/) · [Управление магазином](https://podlivochka.github.io/white-house/admin/) · [Репозиторий](https://github.com/podlivOchka/white-house)

## Управление без собственного сервера

Текущая версия размещается на GitHub Pages. Админка сохраняет каталог в GitHub, после чего сайт автоматически обновляется. Первое подключение и пароль: [docs/GITHUB_ADMIN.md](docs/GITHUB_ADMIN.md).

Владелец один раз подключает ограниченный ключ GitHub и задаёт пароль для своего браузера. Ключ хранится зашифрованным, а право записи проверяет GitHub. На другом устройстве требуется новое подключение. Готового общего пароля в коде нет.

Через админку можно:

- Добавлять, копировать, изменять, скрывать и удалять товары.
- Отмечать «Нет в наличии»: серая фотография, лента и отключённая покупка.
- Загружать до шести фото, выбирать обложку, увеличивать фото на витрине.
- Указывать размеры, отсутствующие размеры, состав, замеры и связанные товары.
- Менять действующую и прежнюю цену; настоящая скидка рассчитывается автоматически.
- Публиковать акции и бонусы, менять баннеры и адрес для заявок.

Изменения появятся после успешной публикации в Actions, обычно через несколько минут. Конфликтующие правки не перезаписывают более новую версию каталога.

## Заказы и почта

На GitHub Pages покупатель заполняет форму и получает готовое письмо со списком вещей, размерами, количеством, телефоном и адресом. Письмо нужно отправить из почтового приложения. Само нажатие «Подготовить письмо» ничего не отправляет и не подтверждает заказ.

На собственном сервере заявка сохраняется в закрытой SQLite, покупателю выдаётся номер, а администратор видит заказ и меняет его статус. Для автоматических писем подключается SMTP; сбои доставки не удаляют заказ. Подробности: [docs/EMAIL_ORDERS.md](docs/EMAIL_ORDERS.md).

Онлайн-оплата, автоматический расчёт доставки и складская система не подключены. Наличие и окончательные условия подтверждает консультант.

## Собственный компьютер или сервер

Для Windows 10: [пошаговый запуск](docs/WINDOWS10.md). Размещение с Docker, Caddy и HTTPS: [docs/SELF_HOSTING.md](docs/SELF_HOSTING.md).

Нужен Node.js 22.13 или новее. Из папки проекта:

```sh
npm ci
npm run admin:set
npm run build
npm start
```

Перед запуском скопируйте `.env.example` в `.env`. Команда `admin:set` использует почту из `ADMIN_EMAIL` и просит ввести пароль в терминале. На Windows используйте `npm.cmd`, если PowerShell блокирует запуск `npm`. Витрина — `http://localhost:3000`, админка — `http://localhost:3000/admin`.

При первом создании базы используется актуальный каталог из репозитория. Существующая база не заменяется при обновлении кода. GitHub Pages и локальная база автоматически не синхронизируются. Администратор локального сервера создаётся отдельно от подключения к GitHub.

## Проверки и публикация

React, TypeScript, Vite, React Router, Radix UI, Lucide, Playwright. Собственный сервер использует Node.js, SQLite и Nodemailer.

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Проверки покрывают шифрование подключения, ограничения доступа, валидацию цен и размеров, конфликты, постоянное хранение, повторные заявки, очередь уведомлений, фотографии, корзину и работу на телефоне. Тесты используют отдельные данные и подставной почтовый сервис; настоящие письма не отправляются.

Для проверки режима Pages:

```sh
VITE_BASE_PATH=/white-house/ VITE_PREVIEW=true VITE_STATIC_PREVIEW=true VITE_ADMIN_BACKEND=github npm run build
npm run test:pages
```

Workflow **Pages preview** проверяет и публикует изменения в `main`. В Settings → Pages выбран источник **GitHub Actions**. Для повторной публикации доступен Actions → Pages preview → Run workflow.

Проверки статической витрины учитывают текущий каталог: добавление и удаление карточек не требуют изменения тестов. GitHub API в браузерных проверках подменяется; настоящий ключ не используется. Просмотр временный: страницы содержат `noindex`.

## Где находятся данные

- `public/content/catalog.json` — товары, предложения, баннеры и почта для заявок на Pages.
- `public/images` и `public/images/uploads` — фотографии витрины.
- `data` — закрытая база и загруженные фотографии собственного сервера; исключена из Git.
- `src/data/socials.ts` — три предоставленных профиля Instagram.
- `shared` — валидация и расчёты; `server` — API, вход, заказы и SMTP.

Публичный репозиторий содержит только материалы витрины. Не добавляйте туда контакты покупателей, пароли, ключи и резервные копии. Файлы и фотографии из истории GitHub остаются доступны даже после скрытия карточки.

В исходном примере указаны разные номера для звонков и WhatsApp; они сохранены. Перед окончательным запуском подтвердите контакты магазина. Для отдельного домена настройте HTTPS, `VITE_SITE_URL`, `VITE_BASE_PATH=/` и `VITE_PREVIEW=false`.

Конфигурация прежнего размещения Netlify сохранена. Она не участвует в текущей публикации GitHub Pages. Заказы и SMTP добавлены в собственный Node.js-сервер.
