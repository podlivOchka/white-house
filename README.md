# White House — Каспийск

Каталог женской одежды магазина White House, ул. Ленина, 39А. Структура витрины вдохновлена Visage Hall; фотографии, модели и цены взяты из предоставленного владельцем примера White House.

## Управление магазином

Рабочий репозиторий: https://github.com/podlivOchka/white-house. Основная версия находится в ветке `main`.

Для запуска сайта и админки на компьютере с Windows 10 используйте [пошаговую инструкцию](docs/WINDOWS10.md).

В `/admin` можно добавлять, редактировать, скрывать и удалять карточки, загружать фотографии, менять цены и наличие, публиковать акции, скидки и бонусы. При статусе «Нет в наличии» фотография становится серой, появляется лента, добавление в корзину отключается. Доступ проверяется сервером для каждого изменения.

Есть два способа запуска:

- **Собственный сервер:** Node.js, SQLite, фотографии в постоянной папке `data`, Docker Compose и Caddy с HTTPS. Полная инструкция — [docs/SELF_HOSTING.md](docs/SELF_HOSTING.md). Администратор создаётся командой `npm run admin:set -- --email brdm.05@mail.ru`; пароль вводится в терминале. Та же команда меняет почту и пароль позже, завершая старые сеансы.
- **Netlify:** серверные функции, Blobs и Netlify Identity. В настройках проекта включите Identity, выберите регистрацию **Invite only**, пригласите `brdm.05@mail.ru`. Серверная переменная `ADMIN_EMAIL` должна содержать этот адрес. Приглашение обрабатывается на `/admin`; там задаётся пароль. Клиент не хранит список администраторов. При смене администратора обновите `ADMIN_EMAIL`, пригласите новый адрес и отзовите старую учётную запись.

Netlify API использует `CATALOG_STORE`, по умолчанию `white-house-demo-catalog`. Для окончательного запуска задайте отдельное имя хранилища. Данные SQLite и Blobs автоматически друг в друга не копируются. Ни Netlify Identity, ни зарегистрированный администратор не создаются простой публикацией исходников: начальную настройку нужно выполнить отдельно.

## Состав проекта

React и TypeScript, сборка Vite, маршрутизация React Router, доступные диалоги Radix UI, иконки Lucide, браузерные проверки Playwright.

- Каталог из восьми моделей, категории, поиск, фильтры по цене и цвету, сортировка.
- Отдельные адреса каталога, новинок, коллекции, акций и каждой модели.
- Избранное и корзина с сохранением на устройстве и синхронизацией вкладок.
- Выбор желаемого размера и цвета, количество, пересчёт стоимости.
- Готовое сообщение для консультанта в WhatsApp. Сам сайт не отправляет сообщение и не подтверждает заказ.
- Адаптация для телефона, клавиатурная навигация, страницы с метаданными и обработка неизвестных адресов.
- Никаких выдуманных скидок, остатков, доступных размеров или отзывов.

## Запуск

Нужен Node.js 22.13 или новее.

```sh
npm install
npm run assets
npm run admin:set -- --email brdm.05@mail.ru
npm run build
npm start
```

После сохранения package-lock.json используйте npm ci.

## Проверка и сборка

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

GitHub Actions выполняет проверки при открытии и обновлении pull request. Серверные проверки используют временную базу: проверяют вход, запрет доступа без сессии, загрузку изображений, валидацию, конфликты версий, статусы и сохранность данных после перезапуска. Браузерные проверки используют отдельный тестовый аккаунт только во временной базе. Собранный сайт и отчёты сохраняются в артефакты запуска.

Сборка витрины находится в `dist`. Для редактирования товаров нужен также API: встроенный сервер или Netlify Functions. Для окончательного домена установите `VITE_SITE_URL`, `VITE_PREVIEW=false` и `VITE_BASE_PATH=/` перед сборкой. При недоступности API рабочая витрина показывает ошибку загрузки, не возвращает удалённые товары из начального списка.

## Предпросмотр через Netlify

Параметры прежнего варианта размещения сохранены в netlify.toml: команда npm run build, каталог dist, Node.js 24. Для текущего просмотра используется GitHub Pages; подключение Netlify для него не требуется.

На текущем этапе VITE_PREVIEW=true: страницы и robots.txt запрещают индексацию. Настройки прямых ссылок и HTTP-заголовков находятся в public/_redirects и public/_headers. Для ручной публикации уже проверенной сборки используйте:

```sh
VITE_BASE_PATH=/ VITE_PREVIEW=true npm run build
npx netlify deploy --dir dist --no-build
```

Перед окончательным запуском нужно подтвердить контакты магазина, установить VITE_PREVIEW=false и указать VITE_SITE_URL. Временная публикация не подключает автоматические обновления из GitHub: для этого отдельно свяжите проект Netlify с репозиторием.

## Просмотр через GitHub Pages

Workflow **Pages preview** собирает и проверяет витрину, затем публикует её при изменениях в `main`. Также доступен ручной запуск: Actions → Pages preview → Run workflow → main.

Перед первой публикацией владелец репозитория должен открыть [Settings → Pages](https://github.com/podlivOchka/white-house/settings/pages) и в разделе Build and deployment выбрать Source → **GitHub Actions**. Настройка Pages требует прав управления репозиторием. Если сборка уже прошла, а публикация остановилась на `configure-pages`, после включения Pages достаточно повторить неуспешное задание в Actions; повторная сборка не нужна, пока артефакт доступен.

Адрес после успешной публикации: https://podlivochka.github.io/white-house/

Проверка именно этого размещения: `VITE_BASE_PATH=/white-house/ VITE_PREVIEW=true VITE_STATIC_PREVIEW=true npm run build`, затем `npm run test:pages`. Pages — только статический просмотр начального каталога. Он не запускает сервер и не сохраняет изменения админ-панели. Проверки используют обычный статический сервер.

В режиме предпросмотра страницы содержат noindex, а robots.txt запрещает индексацию. Фотографии, маршруты и страницы для открытия по прямой ссылке учитывают папку репозитория. Окончательный сайт на отдельном домене собирается с VITE_BASE_PATH=/ и VITE_PREVIEW=false.

## Обновление каталога

Начальные данные товаров и контакты: `src/data/catalog.ts`. После запуска изменения вносятся через `/admin` и сохраняются в базе. Первоначальные фотографии: `public/images`; новые — в постоянном хранилище. Расчёты и фильтрация: `src/lib`, серверная валидация: `shared/catalog.ts`, сервер: `server`, функции Netlify: `netlify/functions`.

Три предоставленных профиля Instagram находятся в `src/data/socials.ts`: White House — основной магазин, WH Collection — собственные изделия, WH of Love — бельё. Они доступны в блоке профилей, подвале, контактах и мобильном меню. Ссылки не содержат параметров отслеживания; публикации Instagram автоматически не копируются.

В примере указаны разные номера: звонки +7 (909) 483-32-42, WhatsApp +7 (967) 406-00-06. Они перенесены без подмены. Владелец должен подтвердить оба контакта перед открытием приёма заказов. Интеграции с оплатой, складом, доставкой и CRM не подключены; согласование заказа выполняет консультант.
