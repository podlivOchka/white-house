# White House — Каспийск

Каталог женской одежды магазина White House, ул. Ленина, 39А. Структура витрины вдохновлена Visage Hall; фотографии, модели и цены взяты из предоставленного владельцем примера White House.

## Состав проекта

React и TypeScript, сборка Vite, маршрутизация React Router, доступные диалоги Radix UI, иконки Lucide, браузерные проверки Playwright.

- Каталог из восьми моделей, категории, поиск, фильтры по цене и цвету, сортировка.
- Отдельные адреса каталога, новинок, коллекции, акций и каждой модели.
- Избранное и корзина с сохранением на устройстве и синхронизацией вкладок.
- Выбор желаемого размера и цвета, количество, пересчёт стоимости.
- Готовое сообщение для консультанта в WhatsApp. Сам сайт не отправляет сообщение и не подтверждает заказ.
- Адаптация для телефона, клавиатурная навигация, страницы с метаданными и обработка неизвестных адресов.
- Никаких выдуманных скидок, остатков, доступных размеров или отзывов.

## Запуск

Нужен Node.js 22.13 или новее.

```sh
npm install
npm run assets
npm run dev
```

После сохранения package-lock.json используйте npm ci.

## Проверка и сборка

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

GitHub Actions выполняет эти проверки при открытии и обновлении pull request. После успешной проверки сохраняет фотографии и lockfile в ветку, а собранный сайт и отчёт — в артефакты запуска. Сообщения покупателям при тестировании не отправляются.

Для размещения используется каталог dist. Файл public/_redirects обеспечивает прямые ссылки при размещении на совместимом статическом хостинге. Для другого сервера настройте возврат index.html для адресов приложения. Установите VITE_SITE_URL в окончательный публичный адрес перед сборкой, чтобы добавить canonical и sitemap.xml.

## Предпросмотр через Netlify

Параметры сборки сохранены в netlify.toml: команда npm run build, каталог dist, Node.js 22. Для подключения приватного репозитория в Netlify выберите ветку site/initial-catalog. Эта ветка содержит версию для просмотра; в main изменения ещё не перенесены.

На текущем этапе VITE_PREVIEW=true: страницы и robots.txt запрещают индексацию. Настройки прямых ссылок и HTTP-заголовков находятся в public/_redirects и public/_headers. Для ручной публикации уже проверенной сборки используйте:

```sh
VITE_BASE_PATH=/ VITE_PREVIEW=true npm run build
npx netlify deploy --dir dist --no-build
```

Перед окончательным запуском нужно подтвердить контакты магазина, установить VITE_PREVIEW=false и указать VITE_SITE_URL. Временная публикация не подключает автоматические обновления из GitHub: для этого отдельно свяжите проект Netlify с репозиторием.

## Дополнительный вариант: GitHub Pages

Workflow Pages preview оставлен для ручного запуска после включения Pages. Автоматический запуск отключён, поскольку Pages в репозитории пока не настроен. В настройках репозитория Settings → Pages выберите Source → GitHub Actions. Для Pages из приватного личного репозитория нужен GitHub Pro. Сам репозиторий можно оставить приватным; опубликованная страница будет открываться по ссылке.

Адрес после успешной публикации: https://podlivochka.github.io/white-house-kaspiysk/

Проверка именно этого размещения: VITE_BASE_PATH=/white-house-kaspiysk/ VITE_PREVIEW=true npm run build, затем npm run test:pages. Проверки используют обычный статический сервер без подмены неизвестных адресов главной страницей.

В режиме предпросмотра страницы содержат noindex, а robots.txt запрещает индексацию. Фотографии, маршруты и страницы для открытия по прямой ссылке учитывают папку репозитория. Окончательный сайт на отдельном домене собирается с VITE_BASE_PATH=/ и VITE_PREVIEW=false.

## Обновление каталога

Данные товаров и контакты: src/data/catalog.ts. Фотографии: public/images. Расчёты и фильтрация: src/lib. Компоненты интерфейса: src/components. Все изображения сначала копируются из исходного сайта скриптом scripts/prepare-assets.mjs; повторно скачивать уже сохранённые изображения не требуется.

В примере указаны разные номера: звонки +7 (909) 483-32-42, WhatsApp +7 (967) 406-00-06. Они перенесены без подмены. Владелец должен подтвердить оба контакта перед открытием приёма заказов. Интеграции с оплатой, складом, доставкой и CRM не подключены; согласование заказа выполняет консультант.
