# Админка без собственного сервера

Витрина: https://podlivochka.github.io/white-house/

Управление: https://podlivochka.github.io/white-house/admin/

Сайт работает на GitHub Pages. Админка сохраняет товары и оформление в репозиторий, после чего GitHub Actions публикует обновление. Собственный компьютер не нужно оставлять включённым.

## Первое подключение

1. Войдите в GitHub под владельцем репозитория `podlivOchka`.
2. Откройте [создание fine-grained personal access token](https://github.com/settings/personal-access-tokens/new).
3. Назовите ключ, например, `White House catalog`, и задайте срок действия.
4. В **Repository access** выберите **Only select repositories**, затем только **white-house**.
5. В **Repository permissions** добавьте **Contents: Read and write**. Доступ к Metadata добавится автоматически. Другие разрешения для админки не нужны.
6. Нажмите **Generate token**. Скопируйте ключ непосредственно в поле **Ключ доступа GitHub** на странице управления магазином. Не отправляйте его в переписку и не добавляйте в файлы проекта.
7. Придумайте пароль от 12 символов, повторите его и нажмите **Подключить и войти**.

Теперь в этом браузере достаточно пароля. Публикация кода сама по себе не создаёт готовый пароль: его задаёт владелец при первом подключении.

## Как устроен вход

GitHub проверяет право изменять репозиторий. Пароль защищает сохранённое подключение на конкретном устройстве: ключ шифруется AES-GCM, а ключ шифрования получается из пароля с помощью PBKDF2. В исходниках, открытом хранилище браузера и репозитории ключа доступа нет.

После обновления страницы нужно снова ввести пароль. Через час без запросов к GitHub сеанс блокируется. Выйти вручную можно кнопкой в верхней части админки.

Это пароль данного браузера, а не общая учётная запись по почте. На другом компьютере или телефоне выполните первое подключение заново; лучше создать отдельный ключ GitHub для каждого устройства. Используйте личный браузер без посторонних расширений.

## Изменение каталога

- **Товары:** добавить или удалить модель, сделать копию, изменить цену, цвета, размеры, состав и описание; загрузить до шести фотографий, выбрать обложку и связанные товары.
- **Нет в наличии:** карточка остаётся на сайте, фото становится серым, появляется лента, покупка отключается. Отдельные отсутствующие размеры можно отметить в редакторе.
- **Скрыть:** убрать карточку с витрины. Это не делает данные секретными в публичном репозитории.
- **Прежняя цена:** укажите её только при реальной скидке; процент рассчитывается из двух цен. Товар также появится в разделе акций.
- **Акции и бонусы:** текст и условия предложений.
- **Оформление:** тексты и фотографии баннеров, почта для заявок. Здесь же меняется пароль текущего устройства.

Загружаются JPG, PNG и WebP до 4 МБ. Удаление фотографии из карточки не удаляет файл из истории GitHub: он может использоваться другим товаром.

После сохранения дождитесь зелёного результата в [Pages preview](https://github.com/podlivOchka/white-house/actions/workflows/pages-preview.yml), затем обновите витрину. Обычно публикация занимает несколько минут. Пока она идёт, покупатели видят предыдущую опубликованную версию.

Если другая вкладка успела изменить каталог, админка покажет конфликт и оставит ваш текст в форме. Скопируйте нужные правки, нажмите **Обновить данные**, повторите изменение с актуальными данными. Старая версия не записывается поверх новой.

## Если пароль забыт или ключ истёк

На странице входа нажмите **Забыли пароль или истёк ключ?**. Подтвердите удаление подключения из этого браузера и подключитесь заново. Каталог останется в GitHub.

Ключи можно отозвать в [настройках GitHub](https://github.com/settings/personal-access-tokens). После отзыва сохранённое подключение теряет доступ независимо от пароля устройства.

## Переезд на свой компьютер

Каталог хранится в `public/content/catalog.json`, фотографии — в `public/images`, история правок — в GitHub. При первом запуске сервера с новой базой актуальный каталог становится начальным содержимым SQLite. Выполните `git pull` и сборку до первого запуска.

Уже существующая база SQLite не заменяется каталогом из GitHub при обновлении кода. Локальная админка и GitHub Pages после переезда не синхронизируются автоматически. Для локального сервера создаётся отдельный вход по почте и паролю: [Windows 10](WINDOWS10.md).

Данные покупателей, пароли и SMTP-настройки в публичном репозитории не хранятся. Работа заявок описана в [EMAIL_ORDERS.md](EMAIL_ORDERS.md).
