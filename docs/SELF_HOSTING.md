# White House на собственном сервере

Проект: https://github.com/podlivOchka/white-house. Сервер запускает сайт, API и вход администратора. Товары и предложения находятся в SQLite, фотографии — в папке `data/images`. Они сохраняются при перезапуске и обновлении контейнера. Пароли хранятся только в виде хеша scrypt, сессии — в HttpOnly cookie. Публичной регистрации нет.

## Что нужно для запуска

- Сервер Linux с Docker Engine и Docker Compose. Можно использовать арендованный VPS или свой постоянно включённый компьютер с публичным адресом.
- Домен, A-запись которого указывает на IP сервера. Если добавлена AAAA-запись, IPv6 тоже должен вести на этот сервер.
- Открытые TCP-порты 80 и 443. Приложение на 3000 доступно только внутри сети Docker.
- Для домашнего компьютера дополнительно нужны постоянная работа, проброс портов на роутере и доступный извне адрес. При CGNAT прямой входящий доступ без дополнительного решения не работает.

## Первый запуск

```sh
git clone --branch site/initial-catalog https://github.com/podlivOchka/white-house.git
cd white-house
cp .env.example .env
```

В `.env` задайте реальный домен без пути:

```dotenv
DOMAIN=shop.example.com
SITE_URL=https://shop.example.com
ADMIN_EMAIL=brdm.05@mail.ru
```

Подготовьте постоянную папку. UID 1000 — пользователь приложения внутри контейнера:

```sh
mkdir -p data
sudo chown 1000:1000 data
chmod 700 data
docker compose build
docker compose run --rm -it app npm run admin:set -- --email brdm.05@mail.ru
docker compose up -d
docker compose ps
```

Команда `admin:set` запросит пароль дважды, ввод скрыт. Минимум 12 символов. Общего или заранее заданного пароля нет. Не передавайте пароль в аргументах команды и не публикуйте его в GitHub.

Caddy получает HTTPS-сертификат автоматически после корректной настройки домена и доступности портов. После запуска откройте `https://ваш-домен/admin` и войдите по e-mail и созданному паролю. Привязка e-mail в собственном сервере — логин, отправка писем не требуется.

## Добавление и изменение товаров

В `/admin` доступны карточки, фото, цены, описание, цвета, новинки и WH Collection. «Нет в наличии» оставляет серую карточку с лентой и отключает добавление в корзину. «Скрыть» убирает карточку с витрины; «Удалить» удаляет её из каталога. Акции, скидки и бонусы редактируются в отдельном разделе. Изменения видны после обновления данных сайта, перехода на другую страницу или возврата во вкладку. Пересборка кода не нужна.

Если другая вкладка уже изменила каталог, старая версия не сохранится поверх неё. Нажмите «Обновить данные», затем повторите изменение. Загруженные изображения автоматически не удаляются при удалении карточки: одно фото может использоваться в нескольких местах.

## Сменить администратора или восстановить пароль

```sh
docker compose exec app npm run admin:set -- --email новый-адрес@example.com
```

Введите новый пароль. Команда заменит единственную учётную запись администратора и завершит старые сеансы. Товары сохранятся. Для смены только пароля используйте текущий адрес. Изменение `ADMIN_EMAIL` в `.env` само по себе не заменяет существующую учётную запись.

## Обновить код

```sh
git pull --ff-only origin site/initial-catalog
docker compose up -d --build
```

## Резервная копия

Сохраняйте всю папку `data`, а не только `store.sqlite`: там же фотографии и файлы журнала базы. Чтобы копия была согласованной:

```sh
mkdir -p backups
docker compose stop app
sudo tar -czf backups/white-house-data-$(date +%Y%m%d-%H%M%S).tar.gz data
docker compose start app
```

Храните копию также отдельно от сервера и ограничьте доступ к ней: она содержит учётную запись администратора. `.env`, `data` и `backups` исключены из Git. При восстановлении остановите приложение, восстановите `data` из выбранной копии, проверьте владельца UID 1000 и запустите приложение. Не удаляйте текущую папку до проверки копии.

## Локальная проверка без Docker

Node.js 24 LTS, либо Node.js 22.13+:

```sh
npm ci
npm run admin:set -- --email brdm.05@mail.ru
npm run build
npm start
```

Для локального запуска задайте `SITE_URL=http://localhost:3000` в `.env`. Адреса: `http://localhost:3000` и `/admin`. Для разработки интерфейса запустите дополнительно `npm run dev`, а в `SITE_URL` укажите адрес Vite, обычно `http://localhost:5173`. API проксируется на 3000. Данные тестов и демонстрационные пароли не используются при обычном запуске.

## Netlify и перенос данных

На Netlify тот же интерфейс использует Netlify Identity и Blobs; на своём сервере — SQLite и собственные сессии. База и сеансы автоматически между ними не переносятся. При окончательном переезде нужно выгрузить актуальный каталог и фотографии из Netlify, импортировать их в сервер, заново задать пароль администратора и проверить данные до переключения домена. Перенос не нужен, если в Netlify оставались только начальные восемь карточек.

Документация: [Docker Compose](https://docs.docker.com/compose/), [Caddy HTTPS](https://caddyserver.com/docs/automatic-https), [Node.js SQLite](https://nodejs.org/api/sqlite.html).
